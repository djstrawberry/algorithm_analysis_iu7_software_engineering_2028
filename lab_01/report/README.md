## Сборка

Из корня репозитория:

```bash
bash lab_01/report/build.sh
```

Нужен XeLaTeX из TeX Live / MiKTeX либо Tectonic. pdfLaTeX не подходит: документ использует `fontspec` и настоящие системные шрифты Times New Roman и Courier New. При установленном latexmk скрипт запускает XeLaTeX через latexmk, который сам выполняет необходимые повторные проходы. Если установлен только XeLaTeX, выполняются три прохода. Tectonic также управляет повторными проходами автоматически.

В текущей рабочей папке шрифты подготовлены в `.fonts/`. Папка игнорируется Git. Полные исходные пакеты Microsoft Core Fonts также сохранены там; их Windows-установщики не запускались. На другой машине можно установить Times New Roman и Courier New штатным способом. Если `.fonts/` отсутствует, преамбула использует системные шрифты с этими именами; автоматической подмены другим шрифтом нет.

Листинги подключены прямо из `../src/` и `../tests/`. Поэтому при переносе проекта сохраняйте структуру папки `lab_01`, Логотип уже скопирован в `figures/b_logo.png`. Схемы строятся в LaTeX с помощью TikZ.

## Оформление

Принято: А4; основной текст 14 пт Times New Roman; интервал 1,5; отступ абзаца 12,5 мм; поля 30/15/20/20 мм; нумерация страниц снизу по центру с учётом титульного листа и без номера на нём. Структурные элементы начинаются с новой страницы. Названия таблиц располагаются над таблицами, подписи рисунков — под рисунками. Формулы, рисунки и таблицы имеют сквозную нумерацию. Листинги набраны Courier New, 12 пт. Каждая из четырёх основных функций поиска размещена целиком на одной странице. Код автоматических проверок хранится в ../tests/test_search.c и не включён в отчёт.

**Расхождение исходных документов:** п. 6.1.1 ГОСТ 7.32–2017 задаёт правое поле 15 мм; предоставленные шаблон и приложение о нормоконтроле указывают 10 мм. Использовано 15 мм по ГОСТ. Если преподаватель требует кафедральный вариант, измените только `right=15mm` на `right=10mm` в `preamble.tex` и повторно соберите документ, поскольку изменится разбиение на страницы.

Схемы алгоритмов используют терминаторы, процессы, решения и предопределённые процессы по ГОСТ 19.701–90 (ЕСПД). ГОСТ 2.105 и 2.106 относятся к текстовым документам и не заменяют стандарт на схемы алгоритмов. Номера стандартов сохранены по переданному комплекту; отчёт не оформляется как диссертация или полный отчёт НИР с регистрационными реквизитами.

## Проверка программы и воспроизведение данных

```bash
bash lab_01/tools/verify.sh
cmake -S lab_01 -B /tmp/aa-build
cmake --build /tmp/aa-build
```

Первая команда проверяет алгоритмы и заново формирует `data/comparisons.csv`. Она считает каждую операцию сравнения искомого значения с элементом: проверки `<`, `>` и `==` учитываются отдельно. Сортировка и условия циклов не входят в счётчик. Это исследование числа сравнений, а не измерение времени в секундах.

Табличные строки `data/comparison_rows.tex` получаются из CSV:

```bash
python3 lab_01/tools/make_report_table.py
```

После изменения алгоритмов обновите экспериментальные данные, таблицу, теоретические формулы и текст выводов, затем пересоберите отчёт. Зафиксированная версия прошла 311 856 проверок результатов, контрольные проверки счётчиков и Valgrind без ошибок и утечек. Число проверок относится к текущему `tests/test_search.c`.

## Исправления кода при подготовке отчёта

- Восстановлен исходный алгоритм Скарупке со `step`, `bit_floor` и `bit_ceil`. Исправлено вычисление ближайших степеней двойки: прежние `pow(2, N/2)` и `pow(2, N/2 + 1)` не вычисляли их корректно. Сохранены подготовка начального участка и цикл с уменьшением шага вдвое. Позиция lower_bound проверяется на равенство искомому значению; при отсутствии элемента возвращается -1. Счётчик учитывает подготовительное сравнение даже при ложном результате и финальную проверку равенства.
- Классический и рекурсивный счётчики приведены к учёту фактически выполненных операций отношений.
- Исходный массив сохраняется для линейного поиска; бинарные работают с отсортированной копией. Программа поясняет, к какому массиву относится индекс.
- Освобождение обоих массивов выполняется в `main`; обработаны ошибки выделения памяти и синтаксически некорректный ввод, исправлена проверка границ при нулевой длине в вспомогательных циклах.

Предоставленный шаблон `report_template_aa` оставлен без изменений. Дополнительный шаблон по ссылке GitHub изучен как справочный материал; класс для ИУ8 не подключён к отчёту кафедры ИУ7.
