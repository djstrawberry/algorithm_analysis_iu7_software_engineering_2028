## Лр 1

Посвящена в т.с. сравнению временной эффективности нерекурсивных и рекурсивных алгосов, решающих одну задачу.

**Вариант №54** — алгоритм поиска в массиве. Дается один вариант на группу.

Составить 4 алгоритма (в отчете далее — со схемами алгосов по ЕСКД) и реализовать их. Алгосы:

1. Линейный.
2. Бинарный нерекурсивный x2
3. Бинарный рекурсивный.

Бинарные нерекурсивные — разные по трудоемкости.
У меня, помимо стандартного алгоса, реализован алгос без ветвления.
Прочитать про него можно [тут](https://probablydance.com/2023/04/27/beautiful-branchless-binary-search/).

Требование - использовать языки со статической типизацией.
У меня старый добрый Си.

При запуске реализации любого выбранного алгоса необходимо вывести индекс найденного элемента, а чтобы вывести данные для таблицы с данными сравнения алгоритмов на материале запуска их реализаций составим расширенные версии тех же функций, возвращающие дополнительные значения, не покрывая эти расширенные функции схемами.

Возможно запросить у пользователя N и заполнить произвольным образом различными значениями одного и того же по емкости числового типа.

Далее программа будет циклически выводить меню, чтобы пользователь мог ввести *x*, выбрать алгос поиска и увидеть результат расчета.

Эта программа — «испытательный стенд»????.

Встает вопрос про то, какой лучший случай, а какой худший.

Говоря о рекурсивной эффективности, будем называть при фиксированном значении N **лучшим случаем** оценки эффективности минимум по всем возможным исходам (пример: поиск элемента в массиве полным перебором потребует минимум 1 сравнение, 1 — оценка числа необходимых сравнений в лучшем случае), **худшим случаем**, соответственно, максимум.

Для любого из упомянутых случаев возможно назвать 1 и более условий наступления такого случая. Так, при поиске полным перебором условие наступления произвольного случая — не первый и не последний элемент, при этом он есть.

Эти условия также нужно выписать к таблице.

Для возможности поиска полным перебором сохранить оригинал или копию сформированного массива.

## Критерии сравнения эффективности алгоритмов

Решаемая задача: поиск значения *x* в массиве *a* размера *N*

| Алг \ Критерий | Лучший случай* | Худший случай* | Накладываемые алгосом огр. | Доп. затраты по памяти |
|:---|:---:|:---:|:---|:---:|
| Линейный поиск | 1 | N | — | i → O(1) |
| Бинарный поиск нерекурсивный | ? | ? | Поддерж. массива отсорт.** | L, R, M → O(1) |
| Бинарный поиск рекурсивный | O(1) | O(log₂N) | | O(log₂N) если принять размер сохр. кадра ф-ции за конст. |

\* — врем. сложность как ассимпт. оценка кол-ва машинных операций (число необх. сравнений) как ф-ции от размера массива

\*\* — данное требование приведет к повышению вычислительных затрат на добавление элементов в массив. Также требуется предварительная сортировка массива — здесь своя оценка сложности.
